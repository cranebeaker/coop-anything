# Engine families: reuse co-op work across games

Before designing anything, check what has been done on the same engine. A framework built
for one game is often most of the work for its siblings, and its bug list tells you where
the engine fights back. Projects named here are in [DIRECTORY.md](../DIRECTORY.md) with
sources; this page is about what carries over.

## Families with a reusable base

| Engine family | Games with co-op work | What carries over |
|---|---|---|
| **Creation Engine / Gamebryo** (Bethesda) | Skyrim (Skyrim Together Reborn, SkyMP), Fallout 4 (Fallout Together, unfinished), Fallout New Vegas (NV:MP), Oblivion (old attempts), Starfield (Creation Engine 2: Starfield Together, PULSAR) | Tilted Online's architecture (TiltedEvolution) was built to span games; Fallout Together lives on a branch of it. Script extenders (SKSE, F4SE, xNVSE) give a supported hook point. Quest state is the common missing piece: most projects sync players and NPCs, not quests. |
| **Unreal Engine 1** | Deus Ex (HX), Unreal (coop, Return to Na Pali coop) | The engine has replication and most games shipped UnrealScript, so co-op is script work. Fixes can ship as a separate package that subclasses and swaps classes. Packet emulation (`PktLag`, `PktLoss`) is built in for testing. Candidates: other UE1 single-player games. |
| **Unreal Engine 2 / 2.5** | Splinter Cell Chaos Theory (official), SWAT 4 (official), Republic Commando (mods), BioShock (BioShock Together) | Same replication model as UE1. |
| **Unreal Engine 4 / 5** | script-modding base UE4SS (used across UE4 games, and for the Poppy Playtime attempt in [games/poppy-playtime](../games/poppy-playtime/NOTES.md)) | UE4SS gives Lua/C++ hooks and console access without a compiler, so co-op is an in-process mod, not a fork. Three traps that each cost test runs on Poppy Playtime: (a) a `summon`-ed actor starts at scale 1 while the player's mesh component can carry a large scale (14.37 there), so a spawned puppet looks absent rather than small — copy the source component's scale; (b) Blueprint animation graphs are often procedural and cast to the owning pawn, so they cannot go on a bare puppet — use a `UAnimSingleNodeInstance` sequence on the same skeleton; (c) every UObject read/write must run on the game thread (`ExecuteInGameThread`) — off-thread mutation crashes the game, and a blocking call there freezes the mod's tick loop with no error logged at all. Many UE4 single-player games still ship the engine netcode: Genesis Alpha One (UE 4.23, [games/genesis-alpha-one](../games/genesis-alpha-one/README.md)) hosts with `open <map>?listen` once `GameEngine.NetDriverDefinitions` points at `IpNetDriver` (its Steam driver was missing in the Epic build), and a second copy joins; the work is then the game's single-player Blueprints (runtime level instances, HUD fade, player init). Crash Bandicoot 4 (UE 4.24.2, Steam, [games/crash-bandicoot-4](../games/crash-bandicoot-4/README.md)): with SteamStub on the exe, UE4SS loaded through `dwmapi.dll` scans the still-encrypted `.text` and finds nothing, so inject `UE4SS.dll` after the title screen appears instead; UE4SS v3.0.1's LoadMap hook then crashes on the game's non-stock `FURL` layout (memcpy in `HookedLoadMap` -> `FURL::FURL`, found with the release's zDEV PDB) until `HookLoadMap = 0` is added to `[Hooks]`, a key the shipped ini omits. |
| **X-Ray** (STALKER) | Shadow of Chernobyl (Shadow of COOP), Clear Sky (Clear COOP), Call of Pripyat, Anomaly | The xrMPE multiplayer extension hosts all three games' co-op as add-ons. Scripts are Lua plus LTX configs inside `.db` archives; `.dscript` files extend base scripts without forking them. |
| **Source / GoldSrc** | Half-Life (Sven Co-op), Half-Life 2 (Synergy, Obsidian Conflict), Dark Messiah, Vampire Bloodlines (VTMBMP) | Server/client split and the SDK make single-player maps playable in multiplayer; the work is mostly entity and map scripting fixes. |
| **RenderWare** (GTA III era) | GTA San Andreas (CoopAndreas, SACoop, GTA SA Open Co-Op, Player 2 CLEO scripts; SA-MP and MTA are free-roam only), GTA Vice City (VC-MP, free-roam only) | Mods load as ASI plugins and CLEO scripts, and [plugin-sdk](https://github.com/DK22Pac/plugin-sdk) covers GTA III, Vice City and San Andreas. CoopAndreas is the reference for story co-op on this engine (players, weapons, vehicles, mission markers). `detect_engine` recognises the family from the `.txd` header (also seen in Manhunt). |
| **id Tech 2 to 4** | Quake, Quake II, Doom 3 (OpenCoop, LibreCoop on dhewm3), Quake 4 | Open source releases (id Tech up to 4) and source ports (dhewm3) put co-op in reach. |
| **CryEngine** | Far Cry (Assault Coop; FarCryCoop, write-up in [games/far-cry](../games/far-cry/README.md)), Crysis (two projects), Prey 2017, Kingdom Come Deliverance 1 and 2; Far Cry 2 (Dunia, a CryEngine 1 derivative: research prototype in [games/far-cry-2](../games/far-cry-2/README.md)) | Mod SDKs and Lua game logic. Dunia has no SDK: its Lua 4.0 runtime, game modes (`gamemodesconfig.xml`) and pawn replication classes can be reached from a `dinput8.dll` proxy; the archives unpack with Gibbed.Dunia. CryEngine 1 (Far Cry): a campaign map runs as a network game with a custom game type that loads the single-player rules; the 8992-bit unreliable stream drops the tail of big snapshots, and area triggers fire only for the machine's own player, both fixable from an ASI by address. |
| **LithTech / Firebird** (Monolith) | F.E.A.R. (Jupiter EX: F.E.A.R. Cooperative, fearservmod), No One Lives Forever 2 (Jupiter: Coop Mod); Middle-earth: Shadow of War (Firebird, research only: [games/shadow-of-war](../games/shadow-of-war/README.md)) | Older LithTech games shipped a real client/server and multiplayer, which the co-op mods build on. Firebird (Shadow of War, 2017) keeps the client/server source layout (`ClientShellDLL`, `ObjectDLL`, `Shared`) and a NetMesh with hosting, but no real-time multiplayer shipped; its console registry (680 named programs and variables) and a hookable debug print make the game self-describing. |
| **RE Engine** | Resident Evil 2, 4 remakes, Dragon's Dogma 2, Resident Evil 7 (coop-re7 prototype, games/resident-evil-7) | Shared tooling (REFramework) across the family; RE Village is still a gap. REFramework's C# source plugins (`plugins/source/*.cs`, hot-reloaded) give sockets and P/Invoke, e.g. Steam relay through the game's own `steam_api64.dll`. Learned on RE7: GameObjects built with `create` + `createComponent` don't render, so instantiate a prefab instead (RE7's `VrDummyPlayer.pfb` makes a good body); shadow-only meshes (`DrawDefault=false`) aren't animated until drawn; animation layers made with `create_instance("via.motion.TreeLayer")` need `.ctor` and `set_Resource(nil)` before `changeMotion` binds; joint edits stick only when written at pre-`PrepareRendering`; `sdk.create_resource` returns an object even for missing files, so it can't test existence; blocking saves at the obvious request methods isn't enough (RE7's chapter jump saved through internal paths), so verify a save blocker with a before/after hash of the save folder. |
| **REDengine 3 / 4** | The Witcher 3 (Witcher Online), Cyberpunk 2077 (CyberpunkMP) | The Witcher 3 ships its script source; annotations (`@wrapMethod`, `@addMethod`) and WitcherNativeBridge (C++ natives callable from script) cover most hooking. Patches change script APIs and native string encoding (5.0 Remastered: UTF-8 strings, CName areas, new Gwent natives), so check a mod against the exact build. |
| **FromSoftware** | Elden Ring, Dark Souls Remastered, Dark Souls III, Nightreign (Seamless Co-op), Sekiro | Seamless Co-op covers several games of the family; its internals are not public, see [how co-op mods work](how-coop-mods-work.md). |
| **Genome** (Piranha Bytes) | Gothic 3 (G3 Together, Myrtana Accord, Gothic 3 Heroes, Sative's Gothic 3 Multiplayer) | The unofficial [Gothic 3 SDK](https://github.com/georgeto/gothic3sdk) (GPL) gives C++ headers and import libraries; plugins are native DLLs in `scripts/` with a `ScriptInit` export. Game logic runs through named scripts whose function pointers a plugin can wrap (`AddHitPoints` for hit authority, `GetAttitude` so NPCs treat a remote player like the hero). The engine only processes NPCs near the camera, so split players need regional ownership. G3 Together (built from zero, ENet direct IP, source: [g3-together](https://github.com/GGM1k3y23/g3-together)) syncs players, NPCs, combat, story, items and saves; the earlier projects share quest state at most or could not be tested. See [games/gothic-3](../games/gothic-3/README.md). |
| **Unity / XNA** | Subnautica (Nitrox), Hollow Knight (HKMP), Outer Wilds (QSB), Celeste (CelesteNet) | C# mod loaders (BepInEx, MelonLoader, Everest) make Unity games the easiest modern targets. |
| **SAGE** (EA Los Angeles RTS) | C&C3 Tiberium Wars (campaign co-op prototype, games/command-and-conquer-3); Generals Zero Hour source is public (GPL, EA) | Lockstep with a lobby; campaign maps can run inside a lobby game if the side stripping (`prepareForMP_or_Skirmish`) and slot sides are skipped. The Generals source names most C&C3/KW/RA3 seams. Watch the per-slot anti-spoofing check when two humans share one side. |
| **ScrapEngine** (MercurySteam) | Clive Barker's Jericho (Jericho Co-op+, [games/clive-barkers-jericho](../games/clive-barkers-jericho/README.md)); Scrapland had official multiplayer | Gameplay is Lua 5.1 (`.lc` = u32 header + zlib bytecode, decompiles with unluac); `-InitLuaLine:` runs your Lua at startup without touching game files, and `OnRenderDebug` gives a per-frame hook. The exe keeps Scrapland's UDP client/server and a Lua `Net` library, but its join packet carries Scrapland ship data; a proxy DLL can repoint unused `Net` entries to your own transport. |
| **GameMaker (YYC)** | Forager (Forager Co-op Mod, 2 to 4 players, [games/forager](../games/forager/README.md)) | YYC games have no GML in `data.win`: every script and object event is a native function, but each one pushes its own name string (`gml_Object_objPlayer_Step_0`) onto the YYC stack trace, so names come back by following the string references, and Ghidra then gives readable pseudo-C (UndertaleModTool still dumps objects and rooms from `data.win`). The runtime structures (RValue, CInstance, the builtin table, `Variable_GetValue`/`SetValue`) are shared by games on the same runtime version, so a `version.dll` proxy with MinHook and a small runtime layer carry over; the addresses do not. A game's own modding API (Forager has one) may be too limited for co-op: Forager's unloads mods on every return to the menu and gives them no file access. GameMaker: Studio 1.4 YYC (Heat Signature, [games/heat-signature](../games/heat-signature/README.md)) differs: the `FORM` data chunk can be embedded in the exe (cut it out by its size field and UndertaleModTool reads it); a function's name pointer is stored with `mov [esp+disp], imm32`, so scanning `.text` for those immediates binds names without Ghidra's hours-long auto-analysis; a `{name, id}` table in `.data` names every variable slot, and `global.X` is the global instance's `yyvars[slot]`. |
| **IW engine** (Call of Duty, id Tech 3 derived) | Modern Warfare 2 (2009): campaign co-op alpha [mw2_coop](https://github.com/stxlvn/mw2_coop), [games/modern-warfare-2](../games/modern-warfare-2/README.md); Modern Warfare 3 (2011): from-zero attempt, [games/modern-warfare-3](../games/modern-warfare-3/README.md); Spec Ops (MW2, MW3) is official 2-player co-op | The MW2 singleplayer exe carries a lockstep 2-player co-op netcode (Spec Ops), and a campaign map loads as a co-op map, so campaign co-op is script work on top: turn off the Spec Ops branches (`is_specialop()`), give player 2 the scripted moments. Scripts are zlib text inside the zones; a `winmm.dll` proxy can replace the script loader to patch them. In co-op, script `getdvar` only sees flagged dvars and retail script errors are silent. The 2026 Steam updates made MW2 and MW3 64-bit (64-bit zones), which broke every 32-bit mod and tool. Whether MW3's `iw5sp.exe` has the same co-op netcode is unchecked. |
| **Java (JVM)** | The Doors of Trithius (two-player co-op mod, [games/the-doors-of-trithius](../games/the-doors-of-trithius/README.md)) | A `-javaagent` (`java.lang.instrument`) loads the mod into the unmodified game JVM, so no game file changes. The game's public classes and its event bus are the hook points; `javap` from the bundled JDK gives every API fact, and a decompiler (CFR, Vineflower) reads the logic. For a single-player game with no netcode, an impersonation window reuses every rule: the host swaps the game's current-player fields (entity, bag, skills, abilities, field of view) to the guest's, runs the vanilla code for the guest's command, then restores them. Turn-based games also need a clock rule for two players far apart. |
| **Santa Monica Studio Kinetica** | God of War 2018 ([games/god-of-war-2018](../games/god-of-war-2018/README.md)); God of War Ragnarök | Despite `.bind` (SteamStub v3.1), `GoW.exe`'s `.text`, `.rdata` and `.data` are unencrypted on disk (flags `0x06`), and jumping `.bind` (`0x14519f310`) to `OriginalEntryPoint` (`0x1403ec680`) lets a second instance run on one PC. Gameplay, quests and Atreus AI run on 1,423 Lua 5.2 scripts (32-bit `float` numbers, unstripped debug info) stored as uncompressed `IFFLuaScriptChunkHeader` chunks inside `.wad` files (`exec/wad/pc_le/`; `IFFHeader.m_Length` is measured from the `ScriptChunk` start). Each character (`heroa00`, `son00`) has its own `lua_State*` with `socket.core` (UDP) and `cmsgpack` built in, but `io`/`os` are omitted and any unhandled Lua error hits `int 3` (`0x14063d629`), so inject config in C++ when compiling overrides in `IFFProcessLuaScriptChunk` (`0x140466de0`) and run the co-op loop inside `son00`'s VM (`crt == game.AI.FindSon()`). |
| **Haxe / HashLink** (Heaps) | Dead Cells: local co-op mod on DCCM ([games/dead-cells](../games/dead-cells/README.md)); online mod DeadCellsMultiplayerMod | The game logic is HashLink bytecode (often embedded in the exe as `hlboot`). [DCCM](https://github.com/dead-cells-core-modding/core) loads C# (.NET) mods that hook any HashLink function and generates a proxy class for every game class; crashlink (bundled) disassembles and decompiles. Dump every function to text once and grep it: decompiling one function at a time is slow and loses call names. Trap: argument-less Haxe enum values are singletons compared by pointer in game code, so an enum value created from C# matches nothing; take the value from the game instead. Strings and objects you hand to the game should be fresh, not cached on the C# side. |

## Rebuilt engines and decompilations

A source port or decompilation turns co-op from reverse engineering into normal
programming. Check for one first.

| Base | Co-op examples | Notes |
|---|---|---|
| OpenMW (Morrowind) | TES3MP | Full quest co-op exists because the engine is open. |
| KeeperFX (Dungeon Keeper) | Archon mode, shared keeper co-op | Lockstep; checksums make a perfect test oracle. |
| Arx Libertatis (Arx Fatalis) | two co-op forks | GPL rewrite. |
| fallout1-ce / fallout2-ce | Fallout 1 and 2 co-op projects | Turn-based combat sync is the hard part. |
| OpenJK (Jedi Outcast) | jedi-outcast-coop and its fork, [games/jedi-outcast](../games/jedi-outcast/README.md) | Same dual-load design as JACoop: joiners run the game code against placeholder entities filled from snapshots, so anything only the host's game code writes must be networked. Single-player "player = entity 0" checks and `kyle` script names are the main source of joiner bugs. |
| OpenJK (Jedi Academy) | JACoop | |
| DevilutionX (Diablo) | built-in multiplayer | |
| reone (KOTOR) | multiplayer demo | Engine still early. |
| Ship of Harkinian (Ocarina of Time) | Anchor, Shipwright-Online, True Co-op | Host authority for enemies and bosses is the frontier. |

## Big gaps on engines with no co-op base yet

From the directory's gap list: 4A Engine (Metro 2033, Exodus), Decima (Horizon, Death
Stranding), id Tech 5 (Wolfenstein The New Order), Frostbite (Dead Space remake),
Northlight (Alan Wake 2, Control), Visceral (Dead Space), Glacier (Hitman Blood Money),
and console-exclusive engines ported to PC (God of War, Ghost of Tsushima, The Last of Us).
These need a team; start with research and a design doc, and claim the game with an issue.

**Visceral Engine caveat (The Godfather II, 2009):** This is a gap in reusable mod/port
infrastructure, not an engine without multiplayer. The Godfather II shipped separate online
match modes, while Dead Space 3 uses the same named engine and has a native two-player online
co-op campaign. No shared framework or reusable campaign-replication layer has been
confirmed. See [the Godfather II research notes](../games/the-godfather-ii/NOTES.md),
[PCGamingWiki: The Godfather II](https://www.pcgamingwiki.com/wiki/The_Godfather_II), and
[PCGamingWiki: Dead Space 3](https://www.pcgamingwiki.com/wiki/Dead_Space_3).
